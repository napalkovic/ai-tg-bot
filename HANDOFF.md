## 0. TL;DR — если читаешь только один раздел

Это личный Telegram-бот «Бобби» для одного человека (и, возможно, второго
доверенного лица). Основной источник ответов — **бесплатный DeepSeek через
веб-чат** (неофициально, по токену аккаунта). Резерв — бесплатные модели
OpenRouter. Картинки рисует **бесплатный FLUX на Hugging Face** (без ключей),
запасной — Pollinations; Cloudflare Workers AI — опционально. История чатов
хранится в **Neon PostgreSQL** (на Render) или SQLite (локально). Хостинг —
**Render Free** + пинг `cron-job.org` каждые 10 минут, чтобы не засыпал.

Последние крупные правки:
1. Починен разбор SSE DeepSeek — теперь и при DeepThink, и при веб-поиске:
   DeepSeek иногда присылает кусок текста в кадре без поля `o`
   (живое наблюдение: `{"p":"response/fragments/-1/content","v":"годня"}`) —
   такие кадры раньше выбрасывались, и половина первого слова терялась
   («Сегодня» → «Се»). Также обрабатываются BATCH-кадры и вырезаются
   служебные маркеры `[reference:N]`, чтобы они не показывались в Telegram.
2. Добавлена генерация картинок через бесплатный FLUX на Hugging Face
   (1024×1024, без регистрации/ключей), с устойчивой загрузкой файла кусками.
3. Расширено распознавание просьб «нарисуй…» и добавлена страховка, если
   модель отвечает «я только текстовая».
4. Добавлена кнопка «🗑 Удалить все чаты» (callback `delall`): в списке чатов,
   с подтверждением, после удаления создаётся новый чистый чат.
5. Второй человек должен теперь тоже уметь рисовать; точная фраза, на которой
   он раньше получал отказ, пока неизвестна — её нужно уточнить у владельца.

**Правки 4 ноября 2026 (вторая волна, см. WORKLOG):**

6. **ИИ знает уровень БПЛА.** Из постов канала оповещений распознаётся текущий
   уровень (🔴 красный / 🟡 жёлтый / 🟢 зелёный), хранится в kv. Отдельного
   сообщения «уровень изменился» НЕТ: подписчикам просто приходит сам пост
   канала. Включённым уровень подмешивается в промпт; на прямые вопросы про
   уровень бот отвечает сам, точно и без записи в историю. **Выключил
   оповещения → ИИ про уровни не знает ничего** и честно это говорит.
   Детали — раздел 13d.
7. **ВК-музыка — ровно 10 треков** по запросу, в порядке выдачи VK, без
   нашей сортировки и дедупликации (было то 5, то «все до 95» — владелец
   уточнил: нужно именно 10).
8. **YouTube и Shorts по ссылке**: бот читает название/описание/субтитры через
   yt-dlp (без скачивания ролика), отвечает по содержанию и запоминает видео
   в текущем чате — как фото. Файл `bot/youtube.py`.
9. **Генерация видео по запросу**: «сгенерируй видео …» или `/video` → короткий
   ролик (2–3 с) с бесплатного HF-пространства LTX-Video (запасное — Wan 2.1

10. **Картинки стали лучше**: FLUX.1-dev → SD 3.5 Large → старое FLUX-демо →

11. **Убраны маркеры `[citation:…]`** из ответов DeepSeek (и `[reference:N]`).

Главные следующие шаги: задеплоить на Render (Manual Deploy), проверить

## 1. Что это за проект

Личный AI-ассистент в Telegram с персонажем **«Бобби»**:

- отвечает на текстовые сообщения с учётом истории текущего чата;
- поддерживает несколько независимых чатов (темы не смешиваются);
- смотрит присланные фото и пересланные посты (фото + подпись);
- у пересланных видео читает только текст, само видео пропускает;
- рисует картинки по описанию («нарисуй кота в шлеме», `/image …`);
- умеет DeepThink (рассуждения) и веб-поиск DeepSeek;
- при недоступности DeepSeek автоматически отвечает резервной моделью;
- никогда не должен называть себя DeepSeek/GPT/Gemini — только Бобби.

Владелец — не программист. Ему нужны:
- бесплатные решения, без банковских карт;
- минимум регистраций и ключей;
- готовые команды для копирования;
- чтобы бот работал без включённого Mac.

## 2. Правила общения и продукта (важно!)

1. **Бот — только «Бобби».** В чате он не должен представляться названием
   модели или компании. В настройках технические названия провайдеров
   допустимы, но в ответах — только Бобби.
2. **Никаких служебных приписок** вроде «🖼 Картинку смотрю через …»,
   «отвечаю через OpenRouter» без необходимости. Пользователь просил убрать
   такие сообщения.
3. **Не просить у владельца ключи/регистрации, если можно сделать бесплатно
   и без ключей.** Это ключевое требование.
4. **Не ломать приватность.** Бот отвечает только ID из `OWNER_IDS`.
5. **Не заставлять Mac работать 24/7.** Целевая схема — Render + Neon.
6. **Объяснять по-русски, коротко, по шагам.** Владелец не любит
   технические детали, но ценит, когда всё работает.
7. **Не удалять и не перезаписывать незнакомые файлы без разбора.** В проекте
   есть локальные правки, которых нет в git.

## 4. Архитектура и поток сообщения

```
Telegram
   │
   ▼
aiogram 3 (long polling)
   │
   ├─ outer middleware _owner_only: пускает только ID из OWNER_IDS
   │
   ├─ routers: common → chats → settings → chat
   │
   ▼
chat.on_text / on_photo / on_video / on_document
   │
   ▼
_locked (asyncio.Lock на user_id, чтобы не было параллельных ответов)
   │
   ▼
_respond
   │
   ├─ 1. «Кто ты?» → IDENTITY_ANSWER (без модели)
   ├─ 2. «Умеешь рисовать?» → CAPABILITY_ANSWER (без модели)
   ├─ 3. «Нарисуй…» → _draw → generate_image
   ├─ 4. Иначе: история из БД → провайдер (DeepSeek web или OpenAI-compatible)
   │       → Streamer по мере генерации правит сообщение в Telegram
   ├─ 5. Если основной провайдер упал до первого текста → резервная модель
   ├─ 6. Если модель ответила «я только текстовый», а просьба про картинку →
   │       удалить отказ и нарисовать картинку
   └─ 7. Сохранить ответ, ds_cid, заголовок чата
```

Ключевые особенности:

- **Один поток на пользователя**: `_locked` не даёт отправить два запроса
  одновременно; второй получает «⏳ Ещё отвечаю…».
- **Стриминг**: `Streamer` редактирует сообщение не чаще раза в 1.2 с,
  разбивает длинные ответы на несколько сообщений, конвертирует Markdown в
  HTML и откатывается на plain text, если Telegram не принял разметку.
- **DeepSeek-ветка**: `ds_cid` хранит идентификатор ветки на стороне
  chat.deepseek.com. При смене провайдера/модели/очистке чата `ds_cid`
  сбрасывается.
- **Резерв**: если DeepSeek не ответил, бот пишет предупреждение и отвечает
  через OpenRouter. Для фото резерв не используется (текстовая модель не
  увидит картинку).

### Важно про git

Локальный git **не является источником истины**:

- `git log` показывает только `dbfb7ca clean import`;
- многие актуальные файлы (`bot/imagegen.py`, `scripts/`, `deploy/`,
  `docker-compose.yml`) — untracked или modified;
- GitHub-репозиторий наполнялся через API (`scripts/deploy_github.py`), а не
  через `git push`.

**Не делай `git reset --hard`, `git checkout .` или `git clean -fd`** — можно
потерять актуальные локальные правки. Источник истины — файлы в рабочей папке
и то, что залито в GitHub. Перед изменениями лучше сделать резервную копию
папки или хотя бы `cp -R bot bot.backup`.

## 6. Конфигурация и переменные

Все настройки читаются из `.env` (локально) или Environment Variables
(Render). Полный пример — `.env.example`.

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `DEEPSEEK_WEB_ENABLED` | `true` | выключить веб-DeepSeek |
| `DEEPSEEK_TOKEN` | — | токен из `session/session.json` (для сервера) |

| `DEEPSEEK_MIN_INTERVAL` | `3` | пауза между запросами, сек |

## 8. DeepSeek web: как работает и что чинили

### Проблема

При включённых **DeepThink + веб-поиск** DeepSeek присылает SSE-поток, в
котором список фрагментов (`fragments[]`) перестраивается: фрагмент `THINK`
или `SEARCH` может исчезнуть, а `RESPONSE` — переехать на другой индекс.
Старый парсер считал «сколько символов уже отправлено» для каждого индекса
отдельно. После перестройки счётчик сбивался, и начало ответа (несколько
первых букв) терялось.

### Решение

Файл: `vendor/deepseek/client.py`, функция `_parse_sse`.

Теперь парсер:

- хранит сами фрагменты (`type`, `content`);
- после каждого кадра собирает **полный текст всех RESPONSE-фрагментов**;
- сравнивает с уже отправленным `emitted`;
- отправляет только новый хвост;
- если снапшот оказался короче уже отправленного — не «отматывает» текст;
- если тексты разошлись — находит общий префикс и отправляет остаток;
- **обрабатывает кадры без поля `o` как APPEND** (живое подтверждение:
  начало ответа приходит строкой `{"p":"response/fragments/-1/content",
  "v":"годня"}` — раньше такой кадр выбрасывался, и «Сегодня» превращалось
  в «Се»);
- **обрабатывает `BATCH`-кадры** (`{"p":"response","o":"BATCH","v":[…]}`),
  разворачивая вложенные операции (создание TOOL_SEARCH/THINK/RESPONSE
  фрагментов может приходить только внутри BATCH);
- вырезает служебные маркеры `[reference:N]` из текста, чтобы они не
  попали в Telegram.

Это устойчиво к перестановкам, объединённым снапшотам, разбиению ответа на
несколько RESPONSE-фрагментов и пропускам поля `o`.

Живая проверка после фикса: запрос «пробей какое число сегодня» с
DeepThink + веб-поиском через настоящий поток вернул полный текст,
начинающийся с «Сегодня **3 ноября 2026 года**, вторник…».

### Синтетические тесты (проходят)

- обычный поток: `Привет` + `, мир` + `!` → `Привет, мир!`;
- ответ разбит на два RESPONSE-фрагмента;
- THINK исчезает, RESPONSE переезжает с индекса 1 на 0;
- SEARCH перед ответом.

Команда для повторной проверки — см. раздел 17.

## 9. Картинки: генерация

Файл: `bot/imagegen.py`.

### Порядок провайдеров

1. **Cloudflare Workers AI FLUX** — если заданы `CLOUDFLARE_ACCOUNT_ID` и
   `CLOUDFLARE_API_TOKEN`.
   - URL: `https://api.cloudflare.com/client/v4/accounts/{id}/ai/run/{model}`.
   - Модель: `@cf/black-forest-labs/flux-1-schnell`.
   - 4 шага, seed случайный.
   - Бесплатный тариф: 10 000 нейронов/день, ~170 картинок 1024×1024.
2. **Бесплатные HF-пространства** — если `IMAGE_FREE_FALLBACK=true`
   (по умолчанию). Перебираются по очереди внутри `_hf_flux`:
   1. **FLUX.1-dev** (`black-forest-labs/FLUX.1-dev`, `IMAGE_HF_SPACE`) —
      основная, даёт заметно более живые картинки;
   2. **SD 3.5 Large** (`stabilityai/stable-diffusion-3.5-large`,
      `IMAGE_HF_SPACE_FALLBACK`) — у неё есть negative prompt (guidance 4.5);
   3. **старое FLUX-демо** (`multimodalart/flux-1-merged`) — «последняя
      соломинка» среди HF.
   - Gradio API: `POST /gradio_api/call/infer`, затем SSE
     `GET /gradio_api/call/infer/{event_id}`.
   - Параметры FLUX-семейства: `[prompt, seed, randomize_seed, width, height,
     guidance_scale, num_inference_steps]`; у SD 3.5 вторым идёт negative
     prompt.
   - Значения: `1024×1024`, `steps=IMAGE_HF_STEPS` (по умолчанию 24),
     `guidance=3.5` (SD 3.5 — 4.5).
   - Ключ не нужен, но `HF_TOKEN` (если задан) подставляется в заголовки и
     повышает квоту бесплатного GPU — иначе анонимная квота на IP кончается
     за несколько генераций, и пространства отвечают ошибкой «лимит/очередь».
   - Результат — WebP/JPEG; скачивается по `url` из события `complete`.
3. **Pollinations** — последний запасной.
   - `https://image.pollinations.ai/prompt/{prompt}`.
   - 768×768, `nologo=true`, `enhance=true`.
   - Бесплатный лимит ~1 картинка/45 с на IP; `POLLINATIONS_TOKEN` убирает
     лимит.
   - Отдаёт только модель `sana` (проверено 4 ноября 2026:
     `GET image.pollinations.ai/models` → `["sana"]`) — качество слабое,
     поэтому используется только когда все HF-пространства не сработали.

### Перевод промпта

Если в промпте есть кириллица, `_to_english()` переводит его через
`https://translate.googleapis.com/translate_a/single` (без ключа). Если
перевод не удался — рисуем по исходному тексту.

### Скачивание файла HF (важный нюанс)

Файловый сервер Hugging Face:

- отдаёт максимум ~16 КБ за один Range-ответ;
- на последнем куске присылает все байты, но **не закрывает соединение**
  (ждёт ещё один байт, которого нет).

Поэтому `_download_ranges()`:

- качает кусками по 16 КБ;
- читает поток и **сам обрывает** его, как только набрал `expected` байт;
- берёт `total` из `Content-Range`;
- обрабатывает `416` как «файл закончился»;
- делает до 4 попыток на кусок;
- принимает частично полученные данные и продолжает с нового offset;
- проверяет, что результат похож на картинку (`PNG`, `JPEG`, `GIF`, `RIFF`).

Живой тест: файл 118 916 байт скачался за ~7.3 с; полная генерация
1024×1024 — ~20.5 с, результат JPEG 306 313 байт.

### Отправка в Telegram

`_to_sendable()`:

- JPEG/PNG отдаёт как есть;
- WebP (и другое) конвертирует в JPEG через Pillow (`quality=92`).
- Если Pillow недоступен — отправляет как есть (но Pillow есть в
  `requirements.txt`).

`_draw()`:

- показывает `🎨 Рисую…`;
- при ошибке редактирует сообщение текстом ошибки;
- отправляет фото с подписью `🎨 {prompt[:900]}`;
- сохраняет в историю текстовую запись `🎨 Нарисовал картинку: {prompt}`;
- **не сохраняет байты картинки и `file_id`** — если делать галерею, это
  нужно добавить.

### Что показывать в `/settings`

`backend_label()`:

- `Cloudflare (FLUX)` — если есть ключи Cloudflare;
- `FLUX.1-dev (бесплатно)` — если включён `IMAGE_FREE_FALLBACK`
  (по умолчанию; фактически это цепочка FLUX.1-dev → SD 3.5 → старое демо);
- `None` — если ничего не настроено.

В `/settings` строка: `Рисую: …`.

## 10. Зрение (анализ фото)

- DeepSeek web **не принимает изображения**.
- Поэтому фото обрабатывает «зрячая» модель резервного провайдера.
- `Settings.vision_config()`:
  - если `VISION_PROVIDER` не задан, берётся резервный провайдер, если он
    `openai`-совместимый;
  - `VISION_MODEL` по умолчанию:
    `nvidia/nemotron-3.5-super-vl:free` для OpenRouter.
- В `_respond` при `images`:
  - выбирается vision-провайдер;
  - картинка прикладывается только к текущей реплике (в истории не хранится);
  - `thinking/search` выключаются.
- Если vision не настроен — бот честно говорит, что не может смотреть фото,
  и предлагает добавить бесплатный ключ OpenRouter.
- В чат **не добавляется** служебная надпись о том, через что смотрит.

### Память про фото (важно!)

Фото смотрит другая модель, поэтому **основная модель DeepSeek изначально
ничего не знает о присланном фото** (фото-реплика не проходит по его ветке).

Решение — `_recap()` в `bot/providers/deepseek_web.py`:

- при продолжении ветки DeepSeek (`resume=True`) в промпт подмешивается
  компактное **напоминание о недавней истории** из БД
  («Напоминание — что происходило в этом чате раньше…»: до 20 реплик,
  каждая до 400 символов, всего до 6000 символов);
- фото-реплика хранится в истории как обычная пара «вопрос пользователя —
  описание зрячей модели», поэтому DeepSeek «помнит» фото и отвечает по
  существу («какого цвета был кот на фото?» — отвечает верно);
- охват реплик тот же, что у `build_history` (`MEMORY_MAX_*`);
- отключается `HISTORY_ON_RESUME=false`;
- выживает и при смене провайдера: любая реплика, прошедшая мимо DeepSeek,
  попадает в напоминание.

Проверено живым E2E-тестом: «Какого цвета был кот на фото?» → DeepSeek
ответил верно по памяти о фото-реплике.

## 13a. Сервисы: музыка

Файлы: `bot/music.py` (поиск/скачивание) и `bot/handlers/services.py` (меню и
обработчики). Зависимость: `yt-dlp` в requirements.txt; в Dockerfile добавлен
`ffmpeg` (конвертация в mp3; на Mac без ffmpeg берётся готовый звук).

**Источник — SoundCloud (с 4 ноября 2026), YouTube убран полностью.**
Причина: YouTube даёт серверам (Render — датацентровые IP) «проверку не
робот» при скачивании, все клиенты (`auto`/`android`/`ios`/`tv_simply`/
`web_safari`/`android_vr`) отваливались. У SoundCloud этой блокировки нет,
треки в mp3, публичный поиск `scsearch` без ключей. Запасные зеркала
(Piped/Invidious) проверены 4 ноября: из 14 живых ни одно не отдало
готовый аудиопоток — идея запасных источников YouTube закрыта.

### Как пользоваться

- Кнопка **«🎧 Сервисы»** → «🎵 Музыка» → **«Где качаем?»** (кнопки:
  🎧 SoundCloud / 🇷🇺 ВКонтакте / ✖️ Отмена) → название трека → 10
  вариантов кнопками → выбор → аудио в чат.- Быстрый путь: `/music <запрос>` (СаундКлауд), `/vkmusic <запрос>` или
  `/vk <запрос>` (ВКタイп; алиасы `/song`, `/track` → SoundCloud).
- **Просто текстом** (без Сервисов): «скачай песню …», «включи музыку …»,
  «загрузи трек …» → если названия нет, бот попросит; если есть — сразу
  спрашивает источник кнопками. Вопросы о возможностях («умеешь
  скачивать музыку?») бот НЕ перехватывает — это уходит обычному чату.
- Отмена любого шага — «✖️ Отмена» или `/cancel`.
- **Привязка ВКонтакте без пароля**: `/vklogin` → страница в браузере
  (вход по коду/QR) → скопированный адрес blank.html → токен в БД.
  Все детали см. раздел «Привязка VK без пароля».

### Сценарий (берёжет слабый сервер)

1. Лёгкий **поиск без скачивания**: ровно **10** кандидатов и у SoundCloud
   (`scsearch10`), и у ВКонтакте (`TRACKS_LIMIT = 10` в `bot/vkmusic.py`).
   У VK запрашивается `count = max(limit*3, 30)` — с запасом, потому что
   треки без прямой ссылки (`url`) отсеиваются; берутся первые 10 **в том
   порядке, в котором их отдал VK**. Никакой своей сортировки (`sort=2`
   убран) и дедупликации нет — так владелец уточнил 4 ноября 2026: «просто
   10 треков по запросу».
2. Бот показывает кандидатов кнопками (`music_choices_keyboard`, callback
   `mus:<index>`, отмена `mus:cancel`); пометок больше нет — каждый трек
   можно скачать; треки живут в FSM-состоянии `MusicStates.choosing`
   (`state.update_data(tracks=…)`).
3. Кнопка выбрана (`cb_pick_track`) → **скачивается только выбранный трек**
   (звук) и отправляется в чат; после доставки список кнопок удаляется
   (просьба хозяина), при ошибке список остаётся — можно выбрать другой.

### Полные треки (30-секундные «отрывки» больше не тема)

У SoundCloud часть коммерческих треков для гостей лежит в виде 30-секундного
отрывка (наблюдение владельца, 4 ноября 2026: Immigrant Song — 0:30).
Решение, которое выбрал владелец («по-человечески», без пометок на кнопках):

1. **Прослушка до выбора / пометки на кнопках убраны** (владелец просил
   вернуть простой список; полные файлы даёт токен SoundCloud).
2. **Проверка после скачивания** (`_ffprobe_seconds`): если ожидали трек
   ≥ 90 с, а файл ≤ 40 с (токен просрочен/не задан) — файл не отправляется,
   бот пишет «SoundCloud отдал только отрывок (проверь токен аккаунта)».
3. **Второй источник — ВКонтакте** (`bot/vkmusic.py`): по аккаунту владельца.
   У большинства треков VK отдаёт прямую mp3-ссылку (поле `url` в
   audio.search) — цельные версии, чего часто нет у SoundCloud.
   HLS-плейлисты (.m3u8) тянет yt-dlp. Ошибки входа — человекопонятные
   (`_human_auth_error`: капча, 2FA, истёкший токен, flood). Треки без
   `url` пропускаются (защита VK Plus). Если VK не привязан — в выборе
   источника бот честно предупредит и предложит либо SoundCloud, либо
   /vklogin.

### Привязка VK без пароля (/vklogin)

Владелец забыл логин/пароль, а старый номер телефона уже не активен.
Поэтому вход по паролю для владельца недоступен — сделан вход по токену:

1. `/vklogin` в боте → бот присылает ссылку на страницу подтверждения
   доступа VK (`oauth.vk.com/authorize`, app Kate Mobile `2685278`,
   scope `audio`, `redirect_uri=blank.html`, `response_type=token`).
2. Владелец открывает её в браузере (на ноутбуке) и входит как может —
   по коду из SMS (нового пароля не нужно), по QR-коду с телефона.
3. VK показывает пустую страницу `blank.html`, в АДРЕСЕ которой сидит
   `access_token=vk1.a.…&user_id=…` — владелец копирует адрес и кидает
   боту в чат.
4. Бот парсит токен (`parse_login_result`), сохраняет его в БД
   (`db.kv_set("vk_token", …)`, таблица `kv`) и подтверждает привязку.
   `remember_db_token` обновляет кэш процесса без перезапуска.
5. `find_tracks` читает токен (`db.kv_get` → кэш `_db_token`) и создаёт
   `vk_api.VkApi(token=…)`. Fallback при пустом токене — direct-auth по
   `VK_LOGIN`/`VK_PASSWORD` (устаревший способ; номер владельца умер).

ВАЖНО: implicit-flow выдаёт токен на срок (expires_in, обычно ~сутки у
не-standalone приложений). Если /vklogin начнёт просить слишком часто —
создать Standalone-приложение на dev.vk.com (там scope audio свободный)
и вписать его client_id в `VK_OAUTH_APP_ID`; `oauth_url()` подхватит
само (приоритет: VK_OAUTH_APP_ID → VK_APP_ID → 2685278).

### Как устроено

- Поиск: yt-dlp `scsearch10:<query>` (SoundCloud, без API-ключей),
  `socket_timeout=25`, до 2 попыток. Таймаут поиска 120 с.
- Прослушки кандидатов больше нет — владелец просил вернуть простой список
  (полные треки даёт токен аккаунта).
- Фильтр кандидатов: не прямой эфир, длительность 1–900 с, есть URL;
  дубликаты по URL отбрасываются.
- Скачивание: только аудио `bestaudio/best`. С ffmpeg — конвертация в mp3
  192 (постпроцессор); без ffmpeg — берём звук как отдаёт сайт.
  «Клиентов» больше нет — они были YouTube-специфичны.
- Лимиты: трек ≤ 15 минут (`MAX_TRACK_SECONDS`), файл **> 30 МБ не качаем**
  (`MAX_AUDIO_BYTES`, просьба хозяина; и в `max_filesize` yt-dlp, и
  повторной проверкой размера файла).
- Отмена поиска: `mus:cancel` обрабатывается обработчиком
  `cb_cancel_choice`, который зарегистрирован **ВЫШЕ** `cb_pick_track`
  (иначе выбор трека съедал `mus:cancel` — был баг «нажимаю отмена, а не
  отменяется»). При отмене бот редактирует сообщение в «❌ Отменил поиск
  музыки» и сбрасывает FSM.
- Ошибки — человекопонятные через `MusicError`: `_human_reason()` переводит
  сырую ошибку yt-dlp в фразу («только для зарегистрированных», «недоступен»,
  «403/429», «таймаут»). При полном провале бот присылает причину **и ссылку
  «Слушай по ссылке»** — так причину видно прямо в чате.
- В историю текущего чата пишется пара «🎵 Музыка по запросу: …» / «🎧
  Отправил трек: …», так что DeepSeek знает контекст.
- Роутер `services` подключён **до** `settings` и `chat`. Пока бот ждёт
  название трека, нажатие «➕ Новый чат» / «🗂 Мои чаты» / «⚙️ Настройки»
  выполняет именно их (прямые вызовы обработчиков в `music_query`).

### Известные ограничения

- Каталог SoundCloud ≠ каталог YouTube: какая-то коммерческая музыка там
  отсутствует, у части треков скачивание запрещено автором («только для
  зарегистрированных»). Тогда бот честно пишет причину и даёт ссылку.
- Обчные поиска: если SoundCloud не нашёл трек — бот предлагает уточнить
  запрос (вернуть YouTube осознанно не возвращаем — там блокировка).
- Через сломанный Mac-интернет (придётся проверить на Render): SoundCloud
  через локальный прокси тоже заблокирован — живой тест только на Render.
- Авторские права: неофициальное скачивание; для личного бота ок, публично
  так публиковать музыку нельзя.

### ТикТок без водяного знака (4 ноября 2026)

Файл: `bot/tiktok.py`; раздел меню: кнопка «🎬 ТикТок» (`svc:tiktok`).

- **Бросить ссылку в любое сообщение чата достаточно** — общий фильтр
  `_has_tiktok_link` ловит `tiktok.com` / `vm.` / `vt.` в любом тексте.
  Обработчик зарегистрирован ВЫШЕ `music_query` (файл `services.py`), так
  что перебивает и режим «жду название трека».
- Скачивание: yt-dlp tiktok-экстрактор, `format best/bv*+ba/b` — отдаёт

- Лимиты: ≤ 10 минут, ≤ 45 МБ (`MAX_VIDEO_BYTES`; Telegram Bot API — 50 МБ —
  запас). Отправка: `answer_video`; если Telegram не принял — `answer_document`.
- Ошибки человекопонятные (`_human_reason`): «не ссылка на видео», «скрыт
  автором», «закрыт для незарегистрированных», «403/429», «таймаут».
- В историю чата пишется пара «🎬 ТикТок по ссылке…» / «🎬 Отправил видео…».

Файлы: `bot/youtube.py` (чтение видео) + `bot/handlers/services.py`
(обработчик `youtube_message`).

- Ловится ссылка в ЛЮБОМ тексте: `youtube.com/watch`, `/shorts/`, `/live/`,
  `/embed/`, короткая `youtu.be`. Обработчик зарегистрирован ВЫШЕ музыкальных
  перехватчиков (рядом с ТикТоком).

  канал, длительность, просмотры, дату, описание и ссылки на субтитры; бот сам

  режет) — запасной `oEmbed` (хотя бы название и автор).
- Дальше вызывается общий `_locked(..., context=info.context)`: «карточка»
  видео подмешивается в промпт ТОЛЬКО этого запроса, а в историю чата
  сохраняется пара «вопрос + 🎬 YouTube: <ссылка>» / ответ модели — поэтому
  DeepSeek «помнит» видео и в следующих сообщениях (та же механика, что с
  фото и `_recap`).
- Если человек прислал только ссылку — вопрос по умолчанию: «Что в этом
  видео? Кратко перескажи основное.» Живая проверка: реальное видео, 2089
  символов субтитров, карточка ~4.7 КБ.

## 13d. Оповещения о БПЛА: посты и уровень (4 ноября 2026)

Файлы: `bot/uav.py` (вся логика) + `bot/handlers/uav.py` (команды/кнопки) +
`bot/handlers/chat.py` (ответы про уровень и вставка в промпт).

- Канал общий (`uav_channel`, по умолчанию `Lipetsk_radar`; владелец задаёт
  `/uav <ссылка>`), личное включение — `uav_user:<id>` = `1`/`0`
  (`/uavon`, `/uavoff`, кнопки в Настройках и под постами).
- Лента читается каждые 15 с (`poll_once`), планка — `uav_last`, при
  включении `skip_backlog` переносит планку на свежий пост (старьё не сыпется).
- **Уровень.** `detect_level` распознаёт уровень в тексте поста: сначала
  явные эмодзи 🔴/🟡/🟢, затем «отбой/миновал/зелёный» → green, «красный
  уровень», «опасность/атака/тревога/прилёт» → red, «БПЛА/дрон» (кроме
  сводок «сбито/перехват/уничтожено») → red, «жёлтый/повышенный/угроза» →
  yellow. `latest_level` берёт самый свежий пост с уровнем; уровень
  «держится», пока не придёт новый пост с уровнем.
- Хранилище в kv: `uav_level` (`red`/`yellow`/`green`), `uav_level_text`,
  `uav_level_post`, `uav_level_at`. Смена канала сбрасывает уровень.
- `poll_once` обновляет уровень на каждом цикле (в kv пишем только когда
  код уровня или пост-источник реально сменились). **Отдельного сообщения
  «уровень изменился» НЕТ** — владелец попросил просто пересылать сам пост
  канала; это и делает обычная рассылка. Функции `announce_level` и
  `_level_banner` удалены, при включении оповещений бот тоже не шлёт
  «текущий уровень» — только подтверждение.
- **ИИ знает уровень.** `ai_level_note(db, user_id)` возвращает скрытую
  вставку в промпт («Текущий уровень опасности БПЛА в регионе: …»), но ТОЛЬКО
  если у пользователя оповещения включены. `chat._respond` подмешивает её к
  последней реплике (в историю не пишет).
- **Прямые вопросы** (`is_level_question`: «какой уровень БПЛА», «уровень
  тревоги», «красный/зелёный уровень», «есть ли угроза атаки», «что с БПЛА?»,
  «тревога», «отбой», просто «уровень») обрабатывает `answer_level_question` —
  бот отвечает сам, точно и мгновенно, без модели и БЕЗ записи в историю.
- **Выключил оповещения → ИИ не знает об уровнях:** вставка не добавляется,
  на прямой вопрос бот отвечает «🔕 выключены, про уровни не знаю». Ответы про
  уровень в историю не сохраняются, поэтому и в recap они не попадут.
  Дополнительно: при выключенных оповещениях `chat._respond` выбрасывает из
  истории для модели ответы ассистента с упоминанием уровня
  (`_mentions_uav_level`), а при самом выключении `/uavoff` / кнопка /
  переключатель в Настройках вызывают `_forget_level_branches` — сброс
  `ds_cid` у чатов пользователя, потому что DeepSeek хранит ветку у себя и
  иначе помнил бы вставки про уровень из прошлых запросов.
- `/uav` показывает текущий уровень по запросу (только при включённых
  оповещениях). `/uavon` и кнопка включения дополнительных сообщений про
  уровень не шлют — просто подтверждение, дальше идут обычные посты.
- Юнит-тесты: 10 фраз распознавания, 12 вопросов фильтра, запись/чтение
  уровня, ответы вкл/выкл — все проходят.

## 13. Личность «Бобби» и защита от самоназваний

Файл: `bot/handlers/chat.py`.

- `SYSTEM_PROMPT` (в `config.py` и `.env`):
  «Тебя зовут Бобби… Ты никогда не называешь себя названием модели или
  компании… Ты умеешь рисовать картинки…»
- `IDENTITY_RE` ловит «кто ты», «как тебя зовут», «какая ты модель»,
  «на какой модели работаешь», `who are you`, `what model` и т.п.
- `IDENTITY_ANSWER`:
  «Я Бобби — твой личный ассистент 🙂 Помню контекст чата, смотрю картинки,
  рисую по описанию и умею искать в интернете.»
- `CAPABILITY_RE` ловит «ты умеешь рисовать?», «можешь генерировать картинки?»
  и отвечает `CAPABILITY_ANSWER` без обращения к модели.
- `SELF_ID_RE` + `_fix_identity()` — страховка: если модель всё же написала
  «я DeepSeek/GPT/Gemini», текст заменяется на «Я Бобби».
- В DeepSeek-промпт персона добавляется в каждом запросе, чтобы старая ветка
  не продолжала звать себя DeepSeek.

**Не убирай эти защиты** без причины: владелец отдельно просил, чтобы бот не
представлялся моделью.

## 14. Распознавание просьб нарисовать

Файл: `bot/handlers/chat.py`.

### Регулярки

- `IMAGE_NOUN_RE` — существительные: картинка, изображение, фото, рисунок,

- `DRAW_GENERIC_RE` — сгенерировать, создать, сделать, згенерувати, створити,
  зробити, generate, create, make.
- `STARTS_CREATIVE_RE` — фраза начинается с «сгенерируй/создай…» (с учётом
  «Бобби, …» и «пожалуйста»).
- `IMAGE_REQUEST_RE` — хочу, хотел, нужна, надо, давай, можешь, можно,
  please, can you…
- `NON_IMAGE_WORDS` — код, json, python, скрипт, текст, стих, таблица, план,
  письмо, эссе, документ, сайт, программа, приложение, презентация, резюме,
  список, инструкция, рецепт, перевод, конспект, домашка, задача, анализ,
  отчёт, email, translate, code, script, essay, letter, resume, table, list,
  plan.
- `LEADING_IMAGE_RE` — фраза начинается с существительного-картинки
  («картинку кота», «фото заката», «мне картинку…»).
- `TEXT_ONLY_RE` — отказы: «только текстовая», «текстовая модель/нейросеть»,
  «не умею/не могу рисовать/генерировать/создавать», «не имею возможности…»,
  `text-only`, `can't draw/generate/create images`, `as an AI text model`.
- `CAPABILITY_RE` — вопрос «умеешь ли рисовать».

### Логика `_image_prompt`

Срабатывает, если:

- есть сильный глагол рисования; **или**
- есть общий глагол + существительное-картинка; **или**
- есть существительное-картинка + просьба; **или**
- фраза начинается с «сгенерируй/создай…» и нет «некартиночных» слов.

Если есть «некартиночные» слова и нет существительного-картинки — не рисуем
(«создай сайт», «сгенерируй план тренировок»).

Очистка промпта убирает:

- «Бобби,» / «Bobby,»;
- «пожалуйста»;
- «можешь/сможешь/можно/давай/хочу/хотел…»;
- «мне» / «мені»;
- «нарисуй/сгенерируй/создай/сделай/…»;
- «нужна/нужен/нужно/потрібна…».

Если после очистки осталось только «картинку/фото/…» — возвращается пустая
строка, и бот спрашивает «Что нарисовать?».

### Страховка

После ответа модели:

```python
if not images and TEXT_ONLY_RE.search(streamer.text) and _wants_image(text):
    # удалить текстовый отказ и нарисовать картинку
```

`_wants_image()` — истина, если:

- есть сильный глагол рисования; или
- фраза начинается с «сгенерируй/создай…»; или
- фраза начинается с существительного-картинки; или
- есть существительное-картинка + просьба.

Это и есть «починка второго человека»: даже если модель отказалась, бот
нарисует сам.

## 19. Известные ограничения и риски

### DeepSeek web

- Неофициальный доступ. Сайт может поменять API — тогда обновлять
  `vendor/deepseek` из апстрима.
- Автоматизация может нарушать правила DeepSeek. Бот выдерживает паузы и
  переиспользует ветки, но риск блокировки аккаунта остаётся.
- С серверных IP DeepSeek чаще показывает «не робот» и может отклонять
  запросы. Тогда бот отвечает резервной моделью.
- Токен живёт ограниченно; на Render `DEEPSEEK_SESSION_MAX_HOURS=720`, но
  при протухании нужно заново выполнить `export_session` на Mac и обновить
  `DEEPSEEK_TOKEN` на Render.
- DeepSeek web не принимает фото — только текст.

### Картинки

- HF Space публичный и бесплатный, может спать/перегружаться. Первая
  генерация может занять 30–90 с.
- HF может изменить Gradio API или удалить Space. Тогда искать другой
  бесплатный Space или включать Cloudflare.
- HF file server throttling уже обработан, но поведение может меняться.
- Pollinations — 768×768, лимит 1 картинка/45 с, может отдавать 402/429.
- Cloudflare-путь не тестировался локально; код есть.
- Если `IMAGE_FREE_FALLBACK=false` и нет Cloudflare — картинки не работают.

### Render

- Free-план засыпает; нужен cron-пинг.
- 750 часов/месяц; при превышении сервис приостанавливается до 1-го числа.
- Диск временный; история только в Neon.
- Перезапуски возможны; бот поднимается сам.

### Прочее

- Второй человек: точная фраза неизвестна. Если после деплоя всё ещё
  отказывает — добавить её в тесты и, при необходимости, в регулярки.
- `OWNER_IDS` должен содержать числовые ID, не `@username`.
- Локальный `.env` содержит только владельца; второй человек, вероятно, только
  на Render.
- `session/session.json` — секрет, никогда не публиковать.
- Локальный git не синхронизирован с GitHub.

### Технические заметки для Mini App

- Telegram Mini App требует HTTPS; Render даёт `https://<service>.onrender.com`.
- Кнопка:

```python
from aiogram.types import InlineKeyboardButton, WebAppInfo

InlineKeyboardButton(
    text="🖼 Мои картинки",
    web_app=WebAppInfo(url="https://<service>.onrender.com/app"),
)
```

- Валидация `initData`:

```python
import hashlib, hmac
from urllib.parse import parse_qsl

def check_init_data(init_data: str, bot_token: str) -> dict:
    pairs = dict(parse_qsl(init_data, keep_blank_values=True))
    received_hash = pairs.pop("hash", "")
    data_check_string = "\n".join(f"{k}={v}" for k, v in sorted(pairs.items()))
    secret_key = hmac.new(b"WebAppData", bot_token.encode(), hashlib.sha256).digest()
    calculated = hmac.new(secret_key, data_check_string.encode(), hashlib.sha256).hexdigest()
    if not hmac.compare_digest(calculated, received_hash):
        raise ValueError("bad initData")
    return pairs
```

- `initData` приходит в `Telegram.WebApp.initData`; передавать на сервер
  заголовком или query, но всегда проверять подпись.
- Не хранить `BOT_TOKEN` во фронтенде.
- Для галереи: `file_id` бессрочный, но если бот удалит сообщение — файл
  может стать недоступен; лучше хранить копию в Telegram (бот уже отправил

## 23. Как вносить изменения (рецепты)

  `chat.router`.

  зарегистрированы раньше.

- `bot/config.py`: `PRESETS`, загрузка ключа.
- `bot/providers/openai_compat.py`: цепочки моделей при необходимости.
- `bot/handlers/settings.py`: провайдер появится автоматически, если
  `available_providers()` его вернёт.

### 4. Добавить картинку-провайдера

- `bot/imagegen.py`: новая функция `_provider(...)`, добавить в
  `generate_image()`.
- Обновить `backend_label()`.
- Обновить README/.env.example.

    (действие + предмет, вопросы о способностях — мимо); vk-api direct-auth
    по `VK_LOGIN`/`VK_PASSWORD` (токен кэшируется; VK_APP_ID по умолчанию
    2685278). Обработчики ТикТока и музыки текстом стоят выше `music_query`,
    чтобы перебивать режим «жду название».
19. **VK без пароля — /vklogin** (3 ноя 2026): владелец забыл логин/пароль,
    старый номер умер. Новая привязка: `/vklogin` → ссылка на
    `oauth.vk.com/authorize` (app 2685278, scope audio) → вход в браузере
    как удобно → скопировать адрес blank.html (`access_token=…`) → бот
    парсит и сохраняет токен в БД (`kv`, ключ `vk_token`, таблица есть в
    обеих схемах) → `remember_db_token` обновляет процесс. `find_tracks`
    резолвит токен (`load_token`: кэш → kv) и делает `VkApi(token=…)`;
    fallback — direct-auth. Истёкший токен → сообщение «сделай /vklogin
    заново». Если Kate Mobile закроют implicit-flow — запас: Standalone
    app на dev.vk.com + `VK_OAUTH_APP_ID`.
20. **Оповещения о БПЛА** (4 ноя 2026): канал ОБЩИЙ (по умолчанию
    `@Lipetsk_radar`, менять — `/uav <ссылка>`), а переключатель ЛИЧНЫЙ:
